# PDF test fixtures

Generated by [`scripts/make-fixtures.mjs`](../scripts/make-fixtures.mjs). Regenerate with:

```sh
npm run fixtures
```

The generator is deterministic — running it again produces byte-identical files
(the only machine-dependent part is which TrueType file it finds, see
[Embedded fonts](#embedded-fonts) below).

Almost every file is **hand-written raw PDF bytes** with a real uncompressed
cross-reference table, because the situations these fixtures cover are exactly
the ones a well-behaved writer such as pdf-lib will never produce. pdf-lib is
used only for standard-14 text metrics, so text can be placed at exact,
assertable coordinates.

All fixtures are verified to load in **both** `pdf-lib` (`PDFDocument.load`) and
`pdfjs-dist` (`getDocument` → `getPage` → `getTextContent` **and**
`getOperatorList`).

## Conventions

- Page size is US Letter, `MediaBox [0 0 612 792]`, unless a fixture is
  specifically about boxes.
- "Page space" below means the coordinate system in `src/core/model.ts`: PDF
  user space translated so the **visible box** (CropBox if present, else
  MediaBox) has its lower-left corner at the origin, rotation not yet applied.

## The fixtures

| `simple-helvetica.pdf` | Standard-14 `/Helvetica`, `/Encoding /WinAnsiEncoding`, **no `/Widths`** array. Four `Tj` ops in one `BT…ET`, moved by `Td`. Third line uses WinAnsi high bytes (`\351 \357 \253 \273`). | Fall back to built-in AFM metrics when `/Widths` is absent. Decode `\351` → `é` etc. via WinAnsi, not Latin-1-by-accident. | `tj-kerning.pdf` | **The important one.** Four `TJ` arrays: one word split by small kerns (`[(O)-16(ther i)-20(nformati)-11(on)]TJ`), one where large negative numbers stand in for spaces with *no space glyphs at all*, one with a positive (tightening) adjustment and a numeric-looking string `(-4)`, and a `Tj` followed by a `TJ` on the same baseline. | Reassemble each `TJ` into one run: `"Other information"`. Convert adjustments ≤ about −180/1000 em into a space when building `text`, but keep `tjAdjustment` so the original advance can be reproduced. Merge the `Tj`+`TJ` pair into one line. | `multi-op-line.pdf` | One visual line built from four separate `Tj` ops, each preceded by its own relative `Td`, alternating `Helvetica-Bold` and `Helvetica` mid-line. Codes `\001\002\003\004` render as "Text". | Resolve codes through `/Differences` first, then `/ToUnicode`; never assume code == ASCII. Take widths from `/Widths`, indexed by `code - FirstChar`. When rewriting, either re-encode into the existing font (possible only for glyphs it already has codes for) or fall back and say so via `EditStats.usedFallbackFont`. |

| `form-xobject.pdf` | Text living inside a Form XObject invoked with `/Do`. | `invisible-ocr.pdf` | A scanned-page stand-in (filled rectangles) plus an OCR text layer at render mode 3 (`3 Tr`), and one genuinely visible caption at `0 Tr`. | Detect `renderMode === 3` and mark those runs `'invisible'`. | `unbalanced-q.pdf` | Content stream that ends with **two** unclosed `q` levels, the inner one having an active clip path (`60 560 300 160 re W n`). Appended content must be wrapped so it is not silently clipped by the leaked clip path — emit the missing `Q`s (or `q … Q`-wrap your own additions) before drawing. Runs under a clip should carry the `'clipping-mode'` blocker only if the clip actually cuts them. |
| `no-text.pdf` | Vector drawing only: filled rectangle, stroked path, an even-odd (`f*`) donut inside a scaled `q…Q`, and a stroked line. | `inline-image.pdf` | Two inline images. The first is unfiltered 8×8 grey (`/BPC 8`, exactly 64 data bytes) whose payload deliberately contains `Tj()xEI q Q BT(` — note the `EI` is preceded by a non-whitespace byte and followed by whitespace, which is the classic trap. The second uses `/F /AHx` so the byte-count shortcut does not apply. Real text and a `TJ` follow both. | The tokenizer must compute the unfiltered image's length from `/W`·`/H`·`/BPC`·`/CS` and skip exactly 64 bytes, and must fall back to a whitespace-anchored `EI` scan only for the filtered one. A naive "search for EI" scanner desynchronises and loses `"Real text AFTER the inline images."` — that missing line is the assertion. |
| `multi-part-contents.pdf` | `/Contents` is an **array of three streams**. Stream 1 opens `BT` and stream 2 closes its `ET`; stream 2 opens another `BT` that stream 3 closes. | Concatenate the streams (with a whitespace separator) before tokenising, but keep a per-stream `streamKey` + offset mapping so a rewrite lands in the right object. Text state must carry across the stream boundary. Rewriting a run in stream 2 must not corrupt streams 1 and 3. |
| `text-state.pdf` | `Tc 2`, `Tw 6`, `Tz 60` and `Tz 140`, `Ts 7` / `Ts -5`, `TL 20` with `T*`, the `'` operator, the `" ` operator (`aw ac string "`), nested `q`/`Q` with `cm` scaling (2× then 0.5×), and a 15°-rotated `Tm`. | Advance width must include `Tc`, `Tw` (single-byte code 32 only) and be multiplied by `Tz/100`. `'` and `"` implicitly do `T*` first, and `"` **sets** `Tw`/`Tc` as a side effect. `Ts` shifts the baseline without changing it. `effectiveSize` must reflect the composed CTM (24 pt for the outer `cm`, 12 pt inside the nested one) and `angle ≈ 0.2618 rad` for the rotated line. |
| `colored-background.pdf` | Full-bleed dark background, a darker panel, light body text on top, an orange accent line, and a light strip with dark text — several distinct fill colours on one page. | Capture `TextRun.fill` per run and reuse it when rewriting. ## Embedded fonts

`embedded-truetype.pdf` and `type0-identity-h.pdf` embed a real TrueType file
found on the build machine. The generator tries, in order:

```
/System/Library/Fonts/Supplemental/Arial.ttf
/System/Library/Fonts/Supplemental/Verdana.ttf
/System/Library/Fonts/Supplemental/Tahoma.ttf
/System/Library/Fonts/Supplemental/Arial Unicode.ttf
/Library/Fonts/Arial.ttf
/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf
/usr/share/fonts/truetype/liberation/LiberationSans-Regular.ttf
```

If none exists it prints a warning and skips just those two fixtures; the rest
still generate. The font is embedded whole (not subset), which is why those two
files are ~760 KB while everything else is under 2 KB.

Because the widths, GIDs and `/ToUnicode` entries are derived from whichever
font was found, tests should assert on **extracted text and relative geometry**,
not on absolute advance widths, for these two files.
